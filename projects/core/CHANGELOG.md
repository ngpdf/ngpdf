# @ngpdf/core

## 1.0.0

### Major Changes

- [#298](https://github.com/ngpdf/ngpdf/pull/298) [`8863c68`](https://github.com/ngpdf/ngpdf/commit/8863c68d1ab5a67b638b7658e8ea00a3d07ea3ed) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - First stable release. From 1.0 on, the public API follows semantic versioning: breaking changes to the elements, their inputs, the style properties, `PdfRenderer` and the server entry point only come in a new major version. Nothing breaks in this release by itself; it groups the v1.0 features listed below (pdf-svg, pages that grow with their content, row views that split across sheets, `min-presence-ahead`, every standard paper size and page sizes with units).

### Minor Changes

- [#294](https://github.com/ngpdf/ngpdf/pull/294) [`43c733e`](https://github.com/ngpdf/ngpdf/commit/43c733e948d8128c9fdc3dab90863f7ef9989b1c) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - `pdf-page` takes `auto` as its height, for receipts and other slips with a fixed width: `[size]="[226, 'auto']"`, `['80mm', 'auto']` or `size="80mm auto"`. Each sheet is as tall as its content plus the page's padding and border, with bottom fixed views and the page number right after the content. A page break you ask for starts a new sheet sized to its own content. A sheet grows to at most 14400pt; taller content breaks onto more sheets, with a development-mode warning. `auto` as the width, or `orientation="landscape"` with an auto height, throws.

- [#290](https://github.com/ngpdf/ngpdf/pull/290) [`a510921`](https://github.com/ngpdf/ngpdf/commit/a510921b93b746d6f62c1fa3a66061893b970aa7) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - New style property `min-presence-ahead`, to keep a section title from sitting alone at the bottom of a sheet. Set it to a length, for example `min-presence-ahead: 80pt`, and an element that would leave less than that much space below it on its sheet moves to the next one. The space is measured above the page number and fixed footers. An element already at the top of a sheet, the last one on a `pdf-page`, or one followed by a page break (`break-after: page` on it or `break-before: page` on the next element) stays where it is. It works on texts, images, views, tables and table rows (a value on a cell counts for its row); a header row ignores it. Elements joined to a moved element with `break-after: avoid` move with it. The default `0` changes nothing; a percentage, a keyword or a negative length throws.

- [#291](https://github.com/ngpdf/ngpdf/pull/291) [`9a9b5e5`](https://github.com/ngpdf/ngpdf/commit/9a9b5e5dfa003e8ebc4221dcf9f23f8fa9d4a87c) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - `pdf-page` `size` now takes lengths as well as points. Each side of `[width, height]` can be a number of points or a length string in `pt`, `px`, `in`, `cm` or `mm`, as in styles: `[size]="['210mm', '297mm']"`. One number or length makes a square page (`[size]="400"`, `size="400"`, `size="10cm"`), and the CSS `@page` form with two lengths works too: `size="210mm 297mm"`. `%`, `em`, `auto` and other units, a side that is zero, negative or not finite, and a string with more than two lengths fail with `ngpdf: unknown page size "<size>" on pdf-page`. A pair with more than two values, which was cut to its first two, now fails the same way. `orientation="landscape"` still always swaps width and height, for these sizes as for names.

- [#289](https://github.com/ngpdf/ngpdf/pull/289) [`ef6cd86`](https://github.com/ngpdf/ngpdf/commit/ef6cd868f2169a2c8dcdde13f8d7c41032ea6789) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - `pdf-page` `size` now knows every standard paper size, so a label on A6, a book on B5 or an envelope on C5 no longer needs its points worked out by hand: ISO A0 to A10, B0 to B10, C0 to C10, 2A0 and 4A0, RA0 to RA4 and SRA0 to SRA4, the Japanese B series as `JIS-B0` to `JIS-B10`, and the US sizes `Executive`, `Folio`, `Tabloid`, `Ledger` and `ID1`. All of them are portrait; `orientation="landscape"` turns them. `Ledger` follows CSS Paged Media and is the same 11 × 17 in sheet as `Tabloid`, so the traditional landscape ledger is `size="Ledger" orientation="landscape"`. Size names now match in any case at run time, so `size="a4"` no longer throws; the `PageSize` type keeps the spellings from the docs table. The existing sizes keep the same points, and an unknown name still fails with `ngpdf: unknown page size "<size>" on pdf-page`.

- [#292](https://github.com/ngpdf/ngpdf/pull/292) [`9121583`](https://github.com/ngpdf/ngpdf/commit/912158359f7640d8b7e09fc6f9346813b1e753b1) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - Add `pdf-svg`, which draws an SVG as vector shapes wherever a `pdf-image` can go. Its `src` takes SVG markup, a `data:image/svg+xml` URL, an http(s) URL (read like an image URL, with `maxImageBytes` and the server's `fetchImage` rule) or a `Blob`. It is sized like an image from the SVG's `width`, `height` and `viewBox`, honours `preserveAspectRatio`, and is clipped to its box. It draws `svg`, `g`, `path` (the whole `d` grammar, arcs included), `rect`, `circle`, `ellipse`, `line`, `polyline`, `polygon`, `use` within the same file, and linear and radial gradients, with fills, strokes, dashes, opacity, `visibility`, the six transform functions and `currentColor`, which is the element's own `color`. Text, images, clip paths, masks, filters, patterns, markers and `<style>` sheets are left out with one development-mode warning each. The parser is ngpdf's own, so it works the same on the server: it reads no DTD or external entities, runs no scripts, fetches no external references, and throws `ngpdf: pdf-svg …` past 1 MB of source, 50,000 elements, 64 levels of nesting, 16 levels of `use` or 1,000,000 path segments, gradient stops, dashes and attributes drawn. Malformed markup throws `ngpdf: invalid SVG: <reason> at <offset>`.

- [#295](https://github.com/ngpdf/ngpdf/pull/295) [`405689e`](https://github.com/ngpdf/ngpdf/commit/405689e390317a1a512be5daeeb4dbc4cde2e59d) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - A row `pdf-view` (or block `pdf-link`) taller than a page now splits across sheets instead of being cut at the bottom, so a two-column layout with a long main column runs over as many pages as it needs. It splits the way a tall table row does: each child breaks on its own, a `pdf-text` between its lines and a column `pdf-view` between its children, and each piece is as tall as its tallest child piece. The row's background and border are sliced per sheet with no border drawn at a cut, and a child stretched to the row's height, such as a shaded sidebar, fills every piece. A row view that fits on a page still moves to the next one whole, so documents that already fit keep their pages. `break-inside: avoid`, a fixed `height` or `max-height`, a `transform` or an `overflow` other than `visible` keep the old behaviour: one unit, cut at the bottom with the dev-mode warning. A single line of a `flex-wrap: wrap` row that is taller than a page now splits the same way.

- [#296](https://github.com/ngpdf/ngpdf/pull/296) [`277daef`](https://github.com/ngpdf/ngpdf/commit/277daefc126e0c198702491ae6de5da4c547f48e) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - `pdf-svg` draws `symbol`, so icon sprites made of `<symbol>` and `<use href="#id">` now show up instead of drawing nothing with a warning. A `symbol` is drawn only through a `use`, as a nested `svg`: its `viewBox` and `preserveAspectRatio` apply, it is placed at the `use`'s `x` and `y` and clipped to the `use`'s `width` and `height`, or else the `symbol`'s own, or else 100% of the drawing around it, skipping a negative size. The limits on `use` count each `symbol` drawn: 16 levels deep, 50,000 elements and the drawing budget.

### Patch Changes

- [#297](https://github.com/ngpdf/ngpdf/pull/297) [`21566d8`](https://github.com/ngpdf/ngpdf/commit/21566d8379c37b9930875b92336e0eea5d2f9c53) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - A `pdf-svg` or `pdf-canvas` with a huge but finite number no longer crashes the render with pdfkit's bare `unsupported number` error. Every number a drawing writes now stays within ±1e9 (about 350 km of page). Past that, a `pdf-svg` fails with `ngpdf: pdf-svg <rect> has the number 1e+22, past ±1e9`, naming the element, and a `pdf-canvas` with `ngpdf: pdf-canvas fill has the number …, past ±1e9`, naming the paint call. This covers path coordinates, shape sizes, stroke widths, dashes, gradient coordinates, transforms and a `viewBox` fitted at a huge scale. Each number is checked in its own coordinates, so a large drawing scaled down onto a page still renders. The writer checks every drawing operation, page size and gradient again before pdfkit sees it.

## 0.9.0

### Minor Changes

- [#281](https://github.com/ngpdf/ngpdf/pull/281) [`e70c53f`](https://github.com/ngpdf/ngpdf/commit/e70c53f5638f291a6001368edf626bd800e88be0) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - `dashed` and `dotted` borders are now drawn as dashes and dots instead of solid lines with a warning. Dashes are 3 times the border width long and dots are as wide as the border, about 2 widths apart, with the gaps fitted so each side starts and ends at its corners. A rounded box with four alike dashed or dotted sides is drawn as one outline, so the pattern runs on round the corners. `border-style` (1 to 4 values) and `border-top-style`, `border-right-style`, `border-bottom-style` and `border-left-style` set the style per side; before, they were ignored. A side whose style is `none` or `hidden` now has a width of 0 whatever order the declarations come in, so `border: none; border-width: 2` no longer draws a border. `double`, `groove`, `ridge`, `inset` and `outset` are still drawn solid with a warning.

- [#275](https://github.com/ngpdf/ngpdf/pull/275) [`0c7ad77`](https://github.com/ngpdf/ngpdf/commit/0c7ad779cac128850a21336abe1966dcef23713f) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - `display: none` now hides an element. It leaves the element and everything inside it out of the document: it takes no space, starts no new sheet and draws nothing, and the fixed views, absolute elements, notes, images and bookmarks inside it go with it. An anchor inside a hidden element does not exist, so a `pdf-link` to it gets the "names no anchor" warning in development mode and is drawn without a link. You can now write `[style.display]="shown() ? null : 'none'"` where you needed `@if`.

  `display: flex` is the default and still accepted. Any other value, such as `block` or `grid`, now throws `ngpdf: invalid value "block" for display on pdf-view; use flex or none`. It used to be ignored without a warning.

- [#287](https://github.com/ngpdf/ngpdf/pull/287) [`286273d`](https://github.com/ngpdf/ngpdf/commit/286273db1a723c5d6e4867f6fbca182ed9d19ed5) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - Rows can wrap. New `flex-wrap` (`nowrap`, `wrap`, `wrap-reverse`), the `flex-flow` shorthand (`<direction> <wrap>`, either part optional, the missing one reset to its default as in CSS) and `align-content` (`stretch` by default, `flex-start`, `center`, `flex-end`, `space-between`, `space-around`, `space-evenly`). These properties used to be ignored silently; a bad value now throws. Each line of a wrapping row is its own unit for pagination, so a long grid of cards or tags breaks between its lines and never through one, and the row gap before a line moved to a new page is dropped. `align-content` is not redone per page: lines keep their places from the single layout. A column with `flex-wrap` whose children went into several columns is kept whole. `flex-wrap` on a `pdf-row` inside a table is ignored, with the `ngpdf: ignored inside tables: pdf-row flex-wrap` development-mode warning.

- [#279](https://github.com/ngpdf/ngpdf/pull/279) [`526e619`](https://github.com/ngpdf/ngpdf/commit/526e6194ad1bfdaaea5e7d6f9ff0723e6e452778) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - `font-weight` now takes any number from 1 to 1000 and the names `thin` (100), `extralight` (200), `light` (300), `normal` (400), `medium` (500), `semibold` (600), `bold` (700), `extrabold` (800) and `black` (900), and `bolder` and `lighter` follow the CSS table from the inherited weight. `providePdfFonts` takes a numeric `weight` per face, so a family registered with Light, Medium or Black faces can use them; `'normal'` and `'bold'` still work as 400 and 700. When a family has no face for a weight, ngpdf picks one as CSS font matching does, and the development warning names the face it drew with.

  Two things change for existing documents. An unknown `font-weight` value such as `heavy` used to draw normal text and now throws `ngpdf: invalid value "heavy" for font-weight on <element>`, with the allowed values in the message. The standard fonts are drawn bold above 500 rather than from 600, which only changes numbers between 501 and 599.

- [#282](https://github.com/ngpdf/ngpdf/pull/282) [`dc17963`](https://github.com/ngpdf/ngpdf/commit/dc17963cd86206d79c478e4ba9f402f07cb52a59) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - Text now sits in the middle of its line, as in CSS: the extra space that `line-height` adds is split in half above and below the text (half-leading), where it used to go all below it. Text in a box with a large `line-height` moves down; with the default `line-height: 1.2`, Helvetica moves down by about 0.14 of its font size. A `line-height` smaller than the font's height moves text up. Line heights, box sizes and page breaks do not change, a link's clickable area still covers the whole line, and underlines and strike-throughs follow the text. In a line with spans of several sizes, the span that reaches highest sets the baseline. The page number is placed the same way.

- [#285](https://github.com/ngpdf/ngpdf/pull/285) [`a1e7688`](https://github.com/ngpdf/ngpdf/commit/a1e76884174fe38f5ecb94e57fd18daf36605e5b) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - Every style property that takes keywords now throws on one it doesn't know. Before, `font-style` drew an unknown value as `normal`, and `break-before`, `break-after` and `break-inside` ignored theirs; now they throw like the others. `font-style` takes `normal`, `italic` or `oblique`, `break-before` takes `auto` or `page`, `break-after` takes `auto`, `page`, `avoid` or `avoid-page`, and `break-inside` takes `auto`, `avoid` or `avoid-page`, in any case. So `break-before: always`, `break-after: column`, `break-inside: avoid-column` or `font-style: oblique 10deg` now fail the render. The message names the value, the property, the element and the keywords the property takes, for example `ngpdf: invalid value "middle" for text-align on pdf-text; use left, center, right or justify`, and properties that already threw (`text-align`, `display`, `border-style`, `white-space`, `text-overflow`, `flex-wrap`, `align-content` and the rest) now list their keywords the same way. `flex-flow` and `vertical-align` end their message with what they take, for example `use baseline, super, sub, a length or a percentage`. `border-style` errors used to read `invalid border style "<value>"`. Unknown properties are still ignored.

- [#277](https://github.com/ngpdf/ngpdf/pull/277) [`473b4a5`](https://github.com/ngpdf/ngpdf/commit/473b4a577324ce66e41cc107c527d766a2b8ba08) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - A `pdf-view` with `fixed="top"` or `fixed="bottom"` now takes its own `width` and places itself with `auto` left and right margins, so `width: 200; margin: 0 auto` centres a header and `margin-left: auto` pushes a footer to the right. A fixed view used to be laid out at the full content width less its margins whatever its `width`, so a document that sets `width` on one now draws it at that width. In the flow, `auto` margins already worked through Yoga, and the docs now say so: `margin: 0 auto` centres a box with a width, `margin-left: auto` pushes a row item to the end, and a box with `margin-top: auto` in a column split across sheets keeps the position it had in the unsplit layout.

- [#280](https://github.com/ngpdf/ngpdf/pull/280) [`b40fdfd`](https://github.com/ngpdf/ngpdf/commit/b40fdfd5f954c8fda58f786c05dba624673cdb9f) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - `pdf-page` takes a `dpi` input (72 by default) for documents made for print at a given resolution. An image on that page with no `width` and no `height` now takes 72 / `dpi` points per pixel, so a 600-pixel image on a `dpi="300"` page is 2in wide. This includes images in fixed views and `pdfPerSheet` content. Images with a size set keep it, `px` in styles stays 1pt, and the page keeps its size in points, so viewers show it at its real size. A `dpi` that is not a finite number above 0 throws `ngpdf: invalid dpi "<value>" on pdf-page`.

- [#276](https://github.com/ngpdf/ngpdf/pull/276) [`b14035d`](https://github.com/ngpdf/ngpdf/commit/b14035da9a58387bf6f80746ab5a521f8febfd97) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - New `row-gap` and `column-gap` properties, and `gap` now takes two values, `gap: <row> <column>`. One value still sets both. Gaps take any length unit ngpdf accepts or a percentage of the container's content box (its height for `row-gap`, its width for `column-gap`); `gap: 10%` used to throw. A negative gap throws. On a `pdf-row` inside a table only the column gap is ignored, and the development-mode warning now names `pdf-row column-gap` instead of `pdf-row gap`; a `row-gap` there no longer warns.

- [#286](https://github.com/ngpdf/ngpdf/pull/286) [`d6dffdf`](https://github.com/ngpdf/ngpdf/commit/d6dffdfa9ed6dc41bcd1d7d0d44f40740226027e) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - `pdf-text` takes `text-overflow: clip | ellipsis`. With `ellipsis` and a fixed `height` or `max-height` on the same `pdf-text`, it keeps the lines that fit in its content box. When text was cut, the last kept line ends with `…`, cut the way `max-lines` cuts it. With `max-lines` too, the smaller number of lines wins. When not even one line fits, the first line is kept, ending with `…` when more text follows it. `clip` is the default and keeps the old behaviour. The property is not inherited, and an `overflow: hidden` parent's height does not count.

- [#283](https://github.com/ngpdf/ngpdf/pull/283) [`109e6d0`](https://github.com/ngpdf/ngpdf/commit/109e6d0bcf785c7c85f386263e0ffe969e19e271) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - A `pdf-span` now takes `vertical-align: baseline | super | sub | <length> | <percentage>` for superscripts and subscripts such as m², H₂O and footnote markers. `super` raises the span by 0.33em and `sub` lowers it by 0.2em of the font size around it, and both draw it at 70% of that size unless the span sets its own `font-size`. A length raises the text by that amount (negative lowers it) and a percentage is of the span's line height; neither changes the size. A nested span moves with the span around it. A line grows when a moved run sticks out of it, and the underline, strike and link area of the span move with its text. `vertical-align` used to be ignored everywhere; on an element other than a `pdf-span` it is still ignored, now with a development-mode warning, and a keyword such as `middle` throws.

- [#284](https://github.com/ngpdf/ngpdf/pull/284) [`3638f15`](https://github.com/ngpdf/ngpdf/commit/3638f15034f83af3c749aa9d73043c4e5e2adcbd) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - New `white-space` property: `normal` (the default, unchanged), `nowrap`, `pre`, `pre-line` and `pre-wrap`, inherited and allowed on `pdf-span`, as in CSS. With `pre-line`, an address or note bound from data keeps its line breaks: `<pdf-text style="white-space: pre-line">{{ address }}</pdf-text>`. `pre` and `pre-wrap` also keep spaces, and tabs go to stops every 8 spaces. `nowrap` and `pre` do not wrap, and a line wider than its box overflows it. `white-space` was ignored before.

### Patch Changes

- [#288](https://github.com/ngpdf/ngpdf/pull/288) [`fa88de8`](https://github.com/ngpdf/ngpdf/commit/fa88de8ac2a315356bf66697d435e77e6f0f3744) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - In a `pdf-table` with `flex-direction: row`, where the header rows sit beside the body rows, a fixed `row-gap` or `gap` no longer pushes a body row below its header. A row split across sheets now starts each piece beside the repeated header, at the header's top, as a percentage `row-gap` already did. When the header is taller than the room left on a sheet, the rows beside it move to the next sheet with it, so the header is not cut at the bottom.

## 0.8.0

### Minor Changes

- [#273](https://github.com/ngpdf/ngpdf/pull/273) [`654893f`](https://github.com/ngpdf/ngpdf/commit/654893fedfd6dc1dd6da71c2d46690547d0213c1) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - Adds `VERSION`, the version of `@ngpdf/core` your app runs, as an Angular `Version` with `full`, `major`, `minor` and `patch` (the same shape as `VERSION` from `@angular/core`). Import it from `@ngpdf/core` to put the version in bug reports, support tools or your own `producer`. The version isn't added to the default `producer`, which stays `ngpdf`, so upgrading doesn't change the bytes of a PDF rendered with a fixed `creationDate`.

- [#269](https://github.com/ngpdf/ngpdf/pull/269) [`6674be4`](https://github.com/ngpdf/ngpdf/commit/6674be44b2892257db392cfd833382730edf61b9) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - Adds `maxImageBytes`, a render option next to `inputs` that caps the size of images fetched from a URL. A response whose `Content-Length` is over the cap is refused before its body is read; otherwise the download stops as soon as the bytes read pass the cap, and the render rejects with `ngpdf: could not load image "<url>": larger than N bytes`. `PdfRenderer`, `renderToBlob`, `downloadPdf`, `pdfResource` and `renderToBuffer` take it, `PdfDownload` takes `pdfMaxImageBytes` and `pdf-viewer` takes `maxImageBytes`. On the server it checks what `fetchImage` returns. Data URLs and bytes are not counted. There is no cap by default.

- [#268](https://github.com/ngpdf/ngpdf/pull/268) [`753b761`](https://github.com/ngpdf/ngpdf/commit/753b7615f97b68177fda0353b6c09ece322bcdd5) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - Adds `pdfPerSheet`, for content in a fixed header or footer that changes from sheet to sheet, such as "Continued on next page" on every sheet but the last and "End of report" on the last. Put `<ng-template pdfPerSheet let-sheet let-total="total">` inside a `pdf-view` with `fixed="top"` or `fixed="bottom"`; the template also gets `first`, `last` and `page`, the `pdf-page` the sheet comes from. It comes with `PDF_ELEMENTS`. The template renders like the rest of the document, with pipes, inputs and services, once per sheet. The view keeps the height of the template's content for a one-sheet document; content taller than that on a later sheet is cut and warns in development mode, so give the view a `height` when its content varies. A `pdfPerSheet` template anywhere but inside a fixed view fails the render.

- [#264](https://github.com/ngpdf/ngpdf/pull/264) [`1eac6b4`](https://github.com/ngpdf/ngpdf/commit/1eac6b4d8cd33b52a6de9eaafe27ce3e8b6719f1) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - A line cut by `max-lines` no longer ends in empty boxes when its last characters come from a font that has no `…`. - [#119](https://github.com/ngpdf/ngpdf/pull/119) [`9844b8c`](https://github.com/ngpdf/ngpdf/commit/9844b8c09f824a4872f67dd07d3162d227a65d09) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - Add `'auto'` table columns: `[columns]="['auto', '1fr', 'auto']"` sizes a column to the widest
  content of its cells on one line, so codes, dates and totals fit without wrapping. `auto` columns
  come after fixed and percentage columns and before `fr` ones, and shrink in proportion when they do
  not fit.

- [#111](https://github.com/ngpdf/ngpdf/pull/111) [`b2ac328`](https://github.com/ngpdf/ngpdf/commit/b2ac3283566eaa8b30ce87af4b0a7e9b25ef2a82) Thanks [@Aaqibhafeezkhan](https://github.com/Aaqibhafeezkhan)! - Add optional document language, application attribution and initial page-view preferences to generated PDFs. Language tags and viewer preferences are validated, and the PDF producer metadata now identifies ngpdf instead of PDFKit.

- [#122](https://github.com/ngpdf/ngpdf/pull/122) [`59006e9`](https://github.com/ngpdf/ngpdf/commit/59006e912ed7cfbadfa0852061ee38a002d81517) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - Add `max-lines` to cut a `pdf-text` to a number of lines. When text was cut, the last kept line ends with `…`, shortened until it fits the box, and the text is only as tall as the lines it keeps. A font without `…` gets `...` instead.

- [#117](https://github.com/ngpdf/ngpdf/pull/117) [`353ff5e`](https://github.com/ngpdf/ngpdf/commit/353ff5e317d1dce5a3c9c3ebc1dfa7e3e5a29b77) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - `pdf-page-number` now works anywhere in a page, not only as a direct child of `pdf-page`. Put it in
  a fixed header to show "Page 2 of 5" on every sheet, or anywhere in the content to show the number
  of the sheet it lands on. A direct child of `pdf-page` still reserves the bottom of every sheet as
  before.

- [#121](https://github.com/ngpdf/ngpdf/pull/121) [`6fb4354`](https://github.com/ngpdf/ngpdf/commit/6fb4354f6bf7dc5182598f4e4a0b185e5faf13ac) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - Add `text-align: justify`. Every line of a paragraph but the last is stretched to both edges of its
  box by widening the gaps between words, across `pdf-span`s and across a page break. The last line,
  a line with one word and a word wider than the box stay at the start.

### Patch Changes

- [#58](https://github.com/ngpdf/ngpdf/pull/58) [`ced90e0`](https://github.com/ngpdf/ngpdf/commit/ced90e026753732aa1254e61d12de6cf2c6945c8) Thanks [@arxigen](https://github.com/arxigen)! - Style keywords are matched case-insensitively and trimmed, as in CSS. `text-align: CENTER` no longer
  throws, and `font-weight: BOLD` and `font-style: ITALIC` are no longer dropped silently. This covers
  `text-align`, `text-decoration`, `flex-direction`, `justify-content`, `align-items`, `align-self`,
  `object-fit`, `font-weight`, `font-style` and `break-before`. Unknown keywords behave as before:
  they throw for `text-align`, `text-decoration`, `flex-direction`, `justify-content`, `align-items`,
  `align-self` and `object-fit`, fall back to `normal` for `font-weight` and `font-style`, and are
  ignored for `break-before`.

- [#63](https://github.com/ngpdf/ngpdf/pull/63) [`df2b007`](https://github.com/ngpdf/ngpdf/commit/df2b007064094fad1a5f6d3201474f9c917bea6e) Thanks [@arxigen](https://github.com/arxigen)! - ngpdf now uses pdfkit 0.20. pdfkit's ES module browser build replaces its old standalone bundle, so the combined PDF engine payload loaded on the first render drops from about 1.5 MB to about 610 KB before compression, and from about 433 KB to about 238 KB gzipped. The initial bundle is unchanged.

  The text and layout of the PDFs you get are unchanged. Their bytes are not: pdfkit 0.20 compresses streams with a different library and writes `/UserUnit 1` on every page.

  A JPEG's EXIF orientation is now read the way pdfkit 0.20 reads it: from the first Exif segment before the image data, even when an XMP segment or a comment comes first. The image's laid-out size keeps matching how pdfkit turns it.

  In an Angular CLI app, pdfkit no longer needs to be listed under `allowedCommonJsDependencies`. Angular may now name fontkit's CommonJS dependencies instead (`brotli`, `clone`, `dfa`, `fast-deep-equal` and `tiny-inflate`).

- [#60](https://github.com/ngpdf/ngpdf/pull/60) [`82788a8`](https://github.com/ngpdf/ngpdf/commit/82788a8ec46366baadd18ab80731f1ba0ab9d7c4) Thanks [@arxigen](https://github.com/arxigen)! - Large images given as percent-encoded data URLs load faster. The decoded image is unchanged.

- [#56](https://github.com/ngpdf/ngpdf/pull/56) [`af957f2`](https://github.com/ngpdf/ngpdf/commit/af957f25849b1b0f2e8b33edafba056c91d5cfbf) Thanks [@jay23606](https://github.com/jay23606)! - Support `thin`, `medium` and `thick` border widths, and reject negative border widths.

## 0.3.0

### Minor Changes

- [#116](https://github.com/ngpdf/ngpdf/pull/116) [`1c7adcf`](https://github.com/ngpdf/ngpdf/commit/1c7adcfc5bda7c96915375ff8429774a0ee8783f) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - Add fixed headers and footers: a `pdf-view` with `fixed="top"` or `fixed="bottom"`, placed directly
  inside a `pdf-page`, is drawn on every sheet of that page, and the content flows in the space
  between them. A footer sits above the `pdf-page-number`.

- [#112](https://github.com/ngpdf/ngpdf/pull/112) [`2e89379`](https://github.com/ngpdf/ngpdf/commit/2e893798fbd7e0c2b4e7c43a8f79df2c07ebe356) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - Add the `pdf-span` element to style part of a text, such as one bold word in a sentence:
  `<pdf-text>Total: <pdf-span style="font-weight: bold">{{ total }}</pdf-span></pdf-text>`. A span
  can change the color, font family, size, weight, style and decoration; the paragraph still wraps as
  one text, and runs of different sizes share a baseline. Characters drawn in a fallback font now
  share the baseline of the text around them instead of its top.

- [#114](https://github.com/ngpdf/ngpdf/pull/114) [`646d783`](https://github.com/ngpdf/ngpdf/commit/646d783589883f8e99860bf1783231f452ca8de1) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - A long `pdf-text` now breaks between its lines at a page break instead of moving to the next page
  whole, or being clipped when taller than a page. `orphans` and `widows` (default 2) set the fewest
  lines kept before and after the break. A text keeps the old behaviour, moving whole, when it has
  `break-inside: avoid`, a fixed `height` or a `max-height`, or when it sits inside a table row or a
  row `pdf-view`.

## 0.2.0

### Minor Changes

- [#110](https://github.com/ngpdf/ngpdf/pull/110) [`b2762ed`](https://github.com/ngpdf/ngpdf/commit/b2762ed5acfa54114d6f31b236a994b68a2de3ad) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - Add custom fonts: register TTF, OTF, WOFF or WOFF2 files with `providePdfFonts` and name them in
  `font-family`. Text in them is not limited to WinAnsi, and each character falls back along the
  `font-family` list to the first font that has it. Only the fonts a PDF uses are embedded, as
  subsets. Documents that name no registered family render exactly as before.

- [#108](https://github.com/ngpdf/ngpdf/pull/108) [`318a305`](https://github.com/ngpdf/ngpdf/commit/318a3054f9c8ef54ff744d42f4c4752df27e1e2c) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - Add the `pdfDownload` directive: `<button [pdfDownload]="Invoice" pdfFileName="invoice.pdf">`
  downloads the document when clicked, marks the button busy and ignores clicks while it renders,
  and reports a failed render through `(pdfError)` and the app's `ErrorHandler`.

- [#107](https://github.com/ngpdf/ngpdf/pull/107) [`1c4d22a`](https://github.com/ngpdf/ngpdf/commit/1c4d22a5d6536b30c46a14ae22c7a301e142b5e4) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - Add `pdfResource` to keep a PDF Blob and object URL current as document inputs change. It also
  exposes loading and error state, revokes replaced URLs, and can debounce bursts of changes.

### Patch Changes

- [#71](https://github.com/ngpdf/ngpdf/pull/71) [`f6cbe03`](https://github.com/ngpdf/ngpdf/commit/f6cbe03a8f70e308c4a7f1f64585e96fd7ca2da3) Thanks [@arxigen](https://github.com/arxigen)! - Text is measured once per render instead of again for every layout pass, so documents with a lot

## 0.1.3

### Patch Changes

- [#34](https://github.com/ngpdf/ngpdf/pull/34) [`3da43bb`](https://github.com/ngpdf/ngpdf/commit/3da43bbc22ae8ad9e24a9f4c12a9c92f26314939) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - `break-before: page` on an element inside a table row or a row `pdf-view`, such as a `pdf-cell`, now starts a new page before that whole row. A `breakBefore` input on an inner `pdf-view` or `pdf-text` does the same. These breaks did nothing before.

- [#37](https://github.com/ngpdf/ngpdf/pull/37) [`0326e89`](https://github.com/ngpdf/ngpdf/commit/0326e892dff88173d7aef29edcdf60a1f43bd5f4) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - A JPEG with an EXIF orientation from 5 to 8, as portrait phone photos usually have, is now laid out at the size it is displayed at, with width and height swapped, so it keeps its aspect ratio instead of being squeezed into the box of the unrotated picture.

- [#35](https://github.com/ngpdf/ngpdf/pull/35) [`ef0e6ad`](https://github.com/ngpdf/ngpdf/commit/ef0e6ad63378cdf0afefa58948e127a9f96ecc79) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - Text from the `date`, `currency` and `number` pipes no longer shows `?` where the locale uses a thin or narrow no-break space (`3:00 PM` in `en-US`, `1 234,50 €` in `fr`): the Unicode spaces U+2000–U+200A and U+205F are drawn as a normal space, and the no-break ones (U+2007, U+202F) as a no-break space, so `3:00 PM` stays on one line. A soft hyphen (U+00AD) is no longer drawn as a hyphen in the middle of a word, and a zero-width space (U+200B) is no longer drawn as `?`; both are removed.

- [#39](https://github.com/ngpdf/ngpdf/pull/39) [`a707598`](https://github.com/ngpdf/ngpdf/commit/a707598c9ceda85bea25f0c95218ad88e7428003) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - A document nested exactly 64 elements deep now renders when its innermost element holds text or an `@if`/`@for` block. The limit counted that text as one more level and rejected the document with `ngpdf: nesting deeper than 64`, which made the real limit 63 for almost every template.

- [#36](https://github.com/ngpdf/ngpdf/pull/36) [`11296e1`](https://github.com/ngpdf/ngpdf/commit/11296e17dbbe4b46497d8f399027135c3afdcbfb) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - A render that fails no longer leaves things behind. If the document component, or a component inside it, throws in its constructor, the services and callbacks of that render's injector are now cleaned up before the error reaches you; before, they stayed alive. Callbacks that a component registered with `inject(DestroyRef)` before the throw still do not run, because Angular does not hand back the partly created component. `download` and `downloadPdf` now remove their temporary link and free the PDF's memory even when the click throws.

- [#33](https://github.com/ngpdf/ngpdf/pull/33) [`cb6a54b`](https://github.com/ngpdf/ngpdf/commit/cb6a54bc197870eb73db6d1852312348515de04e) Thanks [@GabeSilvaDev](https://github.com/GabeSilvaDev)! - `padding: auto`, and `auto` on a `padding-*` side, now throw an `ngpdf:` error instead of becoming 0, since CSS has no `auto` padding. A negative `font-size` or padding now throws as well; negative margins still work, as in CSS. `gap` on a `pdf-row` inside a table is now named in the `ngpdf: ignored inside tables` dev-mode warning.

## 0.1.0

### Minor Changes

- ba61563: First release. Write a PDF as an Angular component: a document is a normal component whose template uses the `pdf-document`, `pdf-page`, `pdf-view`, `pdf-text`, `pdf-image`, `pdf-table`, `pdf-row`, `pdf-cell` and `pdf-page-number` elements. A lazily loaded engine lays it out with Yoga, breaks it into pages and writes it with pdfkit, all in the browser. Importing `@ngpdf/core` adds at most 15 KB gzipped to the initial bundle.
