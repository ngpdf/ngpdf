Every style property that takes keywords now throws on one it doesn't know. Before, `font-style` drew an unknown value as `normal`, and `break-before`, `break-after` and `break-inside` ignored theirs; now they throw like the others. `font-style` takes `normal`, `italic` or `oblique`, `break-before` takes `auto` or `page`, `break-after` takes `auto`, `page`, `avoid` or `avoid-page`, and `break-inside` takes `auto`, `avoid` or `avoid-page`, in any case. So `break-before: always`, `break-after: column`, `break-inside: avoid-column` or `font-style: oblique 10deg` now fail the render. The message names the value, the property, the element and the keywords the property takes, for example `ngpdf: invalid value "middle" for text-align on pdf-text; use left, center, right or justify`, and properties that already threw (`text-align`, `display`, `border-style`, `white-space`, `text-overflow`, `flex-wrap`, `align-content` and the rest) now list their keywords the same way. `flex-flow` and `vertical-align` end their message with what they take, for example `use baseline, super, sub, a length or a percentage`. `border-style` errors used to read `invalid border style "<value>"`. Unknown properties are still ignored.
